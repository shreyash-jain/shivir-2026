# Android app

A Capacitor shell around `../scanner`. It adds no code to the app — the APK
contains the same `index.html`, `jsQR.min.js` and `sw.js` that the web version
serves. `build_www.sh` copies them into `www/` at build time and adds one
file, `config.json`, with the server details. Nothing is compiled or
bundled; there is no build step for the scanner itself.

## Why bother, when the PWA already works offline

- **Installing.** "Open Chrome, go to this URL, menu, Add to Home Screen, yes
  to the prompt" is a five-minute conversation on a cheap handset, times fifty.
  Sideloading one APK is a file transfer and two taps.
- **The camera permission survives.** A PWA can lose its camera grant when
  Chrome clears site settings; the app holds a real Android permission and is
  asked once, at base camp.
- **The screen stays on.** `FLAG_KEEP_SCREEN_ON` is set for the whole activity.
  A lane phone that sleeps between arrivals costs several seconds per wake, and
  at 2.5s/scan that is the difference between clearing a hall and not.
- **Nothing can evict the cache.** Android does not reclaim an installed app's
  assets the way a browser reclaims a service worker cache on a phone that is
  low on storage.

The web version is still the source of truth and still works. This is a
delivery mechanism, not a fork.

## What the native layer actually contains

Two files, both in `android/app/src/main/`:

- `AndroidManifest.xml` — `CAMERA` and `VIBRATE` permissions, portrait
  orientation, and `uses-feature ... required="false"` for the camera so the
  app still installs on an unusual handset rather than being hidden from it.
- `java/org/shivir/attendance/MainActivity.java` — requests the camera
  permission at launch and sets the keep-screen-on flag. About thirty lines.

Everything else under `android/` is generated by Capacitor.

## Building

Needs, once:

```
brew install npm openjdk@21
brew install --cask android-commandlinetools
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"
```

JDK 21 specifically — Capacitor 7 compiles at source level 21 and fails on 17
with `invalid source release: 21`.

Then:

```
cd app
npm install
export ANDROID_HOME=$(brew --prefix)/share/android-commandlinetools
export JAVA_HOME=$(brew --prefix)/opt/openjdk@21
echo "sdk.dir=$ANDROID_HOME" > android/local.properties

npm run apk
```

The APK lands at `android/app/build/outputs/apk/debug/app-debug.apk`
(~4 MB). Install it with `adb install -r <path>`, or copy it to the phones and
open it.

**What gets bundled.** `npm run apk` runs `build_www.sh`, which copies
`../scanner` into `www/` and fetches the live site's `/config.json` into it, so
an APK phone opens straight on the volunteer login with the server already
known. The roll is **not** bundled — it arrives with the volunteer's first
login, gated by their credentials — because APKs get forwarded around on
WhatsApp and the code list must not travel with them.

After editing anything in `scanner/`, re-run `npm run apk`.

## Signing a release build

The debug APK is signed with Android's shared debug key. That is fine for
sideloading onto handsets you control, which is the whole distribution plan
here. If you want `npm run release` to produce something installable, generate
a keystore and add a `signingConfigs` block to `android/app/build.gradle` —
otherwise the release variant builds unsigned and Android refuses it.

## Setting up fifty phones

Install the APK, open it, log in. That is the whole procedure, provided the
first login on each phone happens **with signal** — do it at base camp on
wifi. The app already knows the server (baked in), fetches the schedule and
assignments on open, and downloads the participant roll with the volunteer's
login. After that the phone works with no network, and the same volunteer can
log in again on it offline.

The fallback screen behind ⚙ (**Paste setup from the admin**, load a CSV) is
for a phone that cannot reach the server at all. The `#cfg=` setup *link*
does not work inside the app — it loads from `https://localhost` — so the
same payload is accepted as pasted text.

Rotating the Supabase key: set the new secret in Cloudflare (see `DEPLOY.md`),
rebuild the APK so new installs get it, and existing installs pick it up in
the background the next time they open with signal.

## Gotchas worth knowing

- **`allowMixedContent` is false.** The app is served over `https://localhost`,
  so a Supabase URL typed as `http://` will be blocked. Use `https://`.
- **Portrait is locked.** Volunteers hold these one-handed; a rotation mid-queue
  re-lays-out the video element and costs a scan.
- **The service worker still registers** and is harmless — the assets are local
  already, so it has nothing to fetch. It is left in so the same `index.html`
  works unmodified in both places.
- **`minSdkVersion` is 23** (Android 6). Below that, runtime permissions work
  differently and `BarcodeDetector` is absent; jsQR still covers the decode.
